Building Your First REST API

A practical introduction to routes, HTTP methods and JSON responses.

An API is a contract that lets software communicate. A REST API organizes resources behind URLs and uses standard HTTP methods. For example, a notes API might expose /api/notes for a collection of notes.

Start by listing the resource your product owns: users, notes, products or bookings. Give that resource a predictable URL and decide what the client needs to send and receive before writing the route handler.

GET

Read a list or one resource. A successful response commonly uses status 200.

POST

Create a resource after validating the request body. Return the created record and status 201.

PATCH and DELETE

Update part of a resource with PATCH and remove it with DELETE. Return clear status codes and errors.

Keep the contract predictable

Use consistent JSON shapes, validate every input and never trust values from the browser. Document required fields, authentication rules and error responses so the frontend can handle the API confidently.

Return useful status codes, log unexpected failures on the server and keep secrets out of responses. A small API with a clear contract is easier to secure, test and evolve than a large collection of inconsistent endpoints.
