Authentication Basics for Web Apps

Authentication answers “who is this user?” before an application allows private actions.

Protect passwords

Never store a plain password. Hash it with a slow, modern password hashing algorithm on the server and compare hashes during login. Keep authentication logic away from client-only code.

Sessions and tokens

A session stores a server-side login record and gives the browser a secure cookie. Token-based systems send a signed token with requests. In both cases, use HTTPS, short-lived credentials where practical and safe cookie settings.

Authorize every sensitive action

Authentication identifies a user; authorization checks what that user may do. Validate ownership and permissions on the backend for every protected operation, even when the interface hides the button.
